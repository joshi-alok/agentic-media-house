## 1. Scope

Plan 2 is **milestone 3**: the `desk/` package with all seven stages, the model verifier (G10), the CLI (`run`, `run --dry`, `replay`, `status`), and the verifier evals harness. Everything is built and verified **offline**, behind one model interface, because no API key exists yet.

Out of scope, moved to **Plan 2b** (milestone 4, written once a GitHub repo and a Cloudflare account exist): the GitHub Actions daily workflow, Cloudflare deploy, the hold pull-request flow, the retract CLI, the R2 evidence store, flipping the `LIVE` flags, and real prompt tuning against live models.

Decisions already made by the owner for this plan: the fake-client-first approach; a new `reported` basis for claims that come only from another outlet; Plan 2 is the pipeline only.

## 3. Two patches to the Plan 1 code, done first

1. **Basis `reported`.** `BASES` gains `reported` (a claim whose only source is another outlet); it is never in `SAFE_BASES`. New limitation template (singular and plural): "The {v}{label} figure is reported by {outlet} and was not checked against a primary source." The group key for `reported` claims is the pair (basis, outlet) so each sentence names one outlet. G6 additionally requires: a tier-2 claim must have basis `reported`, and a tier-1 claim must not. The fifth fixture piece, the receipts chip words, the fact-card basis words, the seeded cases and the reason labels are updated.
2. **Limitation groups.** A group is capped at four claims per sentence (a larger group splits into consecutive sentences in claim order). A claim with no `number` value is described by its label alone (no date or name value is used as its figure). `renderLimitation` and `buildLimitations` change together; G8 and the golden piece follow.

Both are test-first patch tasks with seeded-defect cases, like the Plan 1 hardening tasks.

## 5. Model access

One interface, four implementations, and wrappers.

```ts
interface ModelClient {
  json<T>(req: {
    role: 'select' | 'extract' | 'compose' | 'verify'
    model: string
    system: string
    user: string                    // untrusted text arrives inside delimited blocks
    schema: z.ZodType<T>
    maxOutputTokens: number
  }): Promise<{ value: T; usage: { inputTokens: number; outputTokens: number } }>
}
```

- **No tools, ever.** The interface cannot express a tool; a test asserts no request built by any stage or client carries one. Untrusted text is always inside `<source>` blocks, and the system prompt says it is data.
- **`FakeClient`** returns scripted responses per role (including bad ones). All Plan 2 tests and the dry-run demo use it. **`RecordedClient`** replays recorded request/response pairs keyed by a hash of the request, and refuses an unrecorded request.
- **`AnthropicClient`** uses the Anthropic SDK with an API key (`ANTHROPIC_API_KEY`), validates the model's JSON with the Zod schema, and retries once on a parse failure. It is written against the installed SDK's types and exercised only by tests with a stubbed transport until a key exists.
- **`BudgetedClient`** enforces the per-run call count and token ceiling and throws (the run fails closed). **`RetryClient`** does bounded backoff on 429 and 5xx.
- **The Claude Max subscription.** The CLI route (`claude -p --tools "" --json-schema … --output-format json`) can serve as a fifth implementation for attended local runs and for recording real responses. It is not part of Plan 2: its output shape has not been observed on this machine (a nested call from the agent's shell does not return), and the Agent SDK documentation points automation to API keys. It becomes a small follow-up task once the owner has run one test command in a terminal and shared the output. Note that in the CLI, `--tools ""` is what disables tools; `--allowedTools` only pre-approves permission prompts.
- **Models:** select on Haiku 4.5 (`claude-haiku-4-5-20251001`); extract, compose and verify on Sonnet 5.5 (`claude-sonnet-5-5`). The verify model is a config value.

## 6. Stages

Every stage reads the previous artifact and writes its own into `runs/<date>/NN-<stage>.json` (Zod-validated). `desk replay <run>` re-runs the later stages from stored artifacts with a `RecordedClient` and no network.

1. **Discover.** Poll tier-2 feeds (RSS and Atom) from `sources.yml`, skipping sources whose status is `blocked`. Each item becomes a candidate (title, link, date, outlet, beats). Tier-1 newsroom pages are fetched too; their in-site headline links become undated candidates. Deduplicate against published pieces (source URL and title similarity, using the gate's rule; a slug that is taken is handled later by `disambiguateSlug`) and against earlier candidates.
2. **Select.** Deterministic filters first: not already covered, newer than 72 hours (undated candidates are allowed but ranked last, and are read only if their page carries a date inside the window; otherwise the run ends `no-story` with the reason `stale-or-undated`), beat in the vocabulary. The shortlist (at most 15) goes to the select model with the editorial bar from `sources.yml` (`publish_if_any`, `do_not_publish`). The model returns one candidate or none, with reasons. For the chosen candidate, code resolves the tier-1 source: a link in the candidate's page whose host is a tier-1 host from `sources.yml`. No reachable tier-1 source means the story is composed in attributed form and held (spec §6), using `reported` claims.
3. **Fetch.** Politeness is code: a user agent that links to `/method`, `robots.txt` honoured (never worked around), one request per second per host, a byte cap, bounded retries. Every request and every redirect hop is refused if the URL has credentials or the host is `localhost`, an IP literal or resolves to a non-public address (DNS rebinding between the check and the connection is not closed). Text extraction (parse5): drop scripts, styles, navigation, footers and anything hidden (the `hidden` attribute, `aria-hidden`, inline `display:none`, `visibility:hidden` or `font-size:0`, and `<template>`; style sheets are not read); prefer `<article>` or `<main>`; collapse whitespace; read the page's own date (JSON-LD, `article:published_time`, a `<time>` in the article). A snapshot is the extracted text, its SHA-256, the final URL and the retrieval time, stored through an `EvidenceStore` interface (a local directory now; R2 in Plan 2b).
4. **Extract.** The model returns candidate claims, each with an exact quotation. Code decides what survives: the quotation must occur in the snapshot (whitespace-normalised) and offsets are computed by code; at most 300 characters; every `value` raw string occurs inside the quotation as a whole token; every word of the `label` (at most six) is a word of the quotation, a plain function word or on the allow-list; the claim `text` holds no figure, date or capitalised word the quotation lacks and no word of four or more letters that is neither in the quotation nor one of 25 plain grammar words, and the short negations (no, not, nor, non) must be in the quotation too (entry item 3); `basis` must be allowed for the source kind (company newsroom: press-release, datasheet, briefing, demo; arXiv: paper; SEC: filing; ISO, OSHA, EU: standard; tier 2: reported; `measured` is never allowed from a page); a page of an unknown kind is not read. A rejected claim is dropped and logged with its reason. Fewer than three surviving claims ends the run with outcome `no-story`.
5. **Compose.** The model returns a structured draft (sentences with claim IDs; never MDX). Code supplies what the model must not write: the slug (from the title, then `disambiguateSlug`), `publishedAt` (the run date), the author (`DESK_AUTHOR_NAME`), and the limitation sentences (`buildLimitations` over the cited claims). The prompt states the gate's rules (entry item 2): open sentences with a word from the cited claims or a plain function word; start with a capital or a digit; headings lowercase except words from the section's claims; no empty sections or repeated neighbouring headings; digits, never "half", "twice" or "double".
6. **Verify.** The gate (G1–G9) runs first. Then G10: the verifier model judges, for every fact sentence and every heading, whether the cited spans entail it, and whether each `basis` and `status` label is supported. Any verdict other than `entailed` fails. G10 runs only on a draft the gate has cleared. A failing sentence or heading goes back to compose with only the failing items, at most two revision rounds, then the piece is held; a structural failure (length, takeaways, sections, categories, analysis share, a basis or status) is held without a revision round. Verify writes `05-compose.json` and `06-verify.json`.
7. **Publish or hold.** Publish: `renderDraft` with `release: 'auto'` and `updatedAt` per the rules, written into `site/src/content/news` and `site/src/content/ledger`, `desk-state.json` updated, one local git commit (the push and the PR flow are Plan 2b). Hold: the draft, gate report and verifier verdicts are written under `runs/<date>/held/`, the hold is added to `desk-state.json` with its reason codes, and nothing reaches the site. `no-story` and `failed` outcomes update `lastRun` only. Every run that is not dry makes one local commit (a held, `no-story` or `failed` run commits the desk state only); nothing is ever pushed.

## 7. CLI

`desk run [--date YYYY-MM-DD] [--dry] [--client fake|recorded|api] [--sources fixtures|live] [--force-new] [--cassettes <folder>] [--config <path>]`, `desk replay <runDir> [--sources …] [--cassettes …] [--config …]`, `desk status [--config …]`. Exit codes: 0 for published, held or no-story, 1 for failed, 2 for a usage error or a refused combination (for example `--client fake` or `--sources fixtures` without `--dry`, or a live run whose user agent still points at a `.example` host). `--dry` writes artifacts but never touches `site/` or git. The orchestrator takes a run lock (a lock file), so two runs cannot overlap, and a second run for the same date is refused unless `--force-new` is given.

## 8. Testing and verification (offline)

- **Stage tests** with the fixtures and the `FakeClient`; stage contract tests on every artifact schema.
- **An adversarial matrix, end to end.** Scripted bad composers and extractors (an invented number, an invented name at a sentence start, a lowercase opening, an unsupported quotation, a swapped figure, a tier-2 claim presented as fact, a heading that asserts something) each run through the whole pipeline; every one must end in `hold` or a revision, never `publish`. A clean script ends in `publish`.
- **Fail-closed tests:** an unreachable source, a robots block, a malformed feed, a schema-invalid model reply, a budget overrun, an unreachable evidence store.
- **No-tools test** for every client and stage; **no-network test** for `replay`.
- **Verifier evals harness:** the labelled set (60 sentences: 20 supported, 20 unsupported, 20 subtly distorted) with their cited spans, a harness that reports precision and recall for any `ModelClient`, tested with scripted clients that are perfect, lazy and over-strict. Plan 2 verifies the harness, not a model's score; thresholds are frozen in milestone 5.
- Same discipline as Plan 1: each task test-first, each part replayed mechanically from a clean clone, a mutation pass over new code, a closure review, and a full cold replay before it is declared done.

## 9. Error handling

Everything fails closed. Fetch: bounded retries, `robots.txt` honoured, a source that cannot be fetched is skipped and noted in the run's discover artifact (`sources.yml` is not edited). Model calls: bounded retries, one repair attempt on a schema failure, then the stage fails; truncation and refusal fail the stage; the budget wrapper aborts the run. A stage that throws ends the run with outcome `failed`, a recorded reason, and nothing published.

## 10. Decisions made here, for you to veto

- Discovery is feed-driven (tier-2 feeds) with newsroom headline links as undated extras; the tier-1 source of a chosen story is found from links in the candidate's page. Newsroom scraping is generic and will be brittle for some sites; a per-site adapter is a later addition.
- Claims below three survivors end the run with `no-story` rather than a thin piece.
- A group of limitation claims is capped at four per sentence; a claim with no number is named by its label.
- The 72-hour recency window and the 15-candidate shortlist are defaults in `desk/src/config.ts`; a YAML file passed with `--config` overrides them.
- The Max subscription is not a code path in Plan 2 (§5).

## 11. Risks

| Risk | Mitigation |
|---|---|
| Prompts are written but never tried on a live model | Everything the gate and the extract validators enforce is code and is tested against adversarial scripts; prompt quality is a Plan 2b follow-up with recorded real responses |
| Newsroom pages differ wildly | Generic extraction, per-run logging of what was extracted, `no-story` instead of guessing |
| Verifier and composer share a model family | Deterministic checks first; the verifier is measured by evals; the model is a config value |
| Cost | Per-run call and token budgets, a spend cap on the key when one exists |

## 12. Findings closed after the plan was written (tasks 41–50)

A closure review of the first five parts found two holes that the offline tests had not exercised, and several smaller ones. They were closed before Plan 2 was declared done:

- **Values are whole tokens.** A value `2` was accepted inside `12 weeks`; `valueInQuote` now requires a boundary on each side, in the gate (G4) and in Extract.
- **Model-written claim text and label ground nothing.** The first word of a sentence is grounded only in the verbatim quotation, the name values and the outlet; a label's words must come from the quotation; the receipts page shows the label and the quotation, never the model's paraphrase.
- **Hidden page text is not evidence**, **an undated candidate needs a dated page inside the window**, **the fetcher refuses non-public addresses on every hop**, **the reserved headings cannot be used by a composer**, and **model-written claim ids reach a prompt only after they are filtered to known ids**.
- **Wiring and wording:** `--config` is read, a live run with a placeholder user agent is refused, a guard makes `fetch` and raw sockets throw in tests, the demo's last line says it proves plumbing and replay equality and not model quality, and test data uses no real company or paper.

What the review left open is listed in Task 50's Plan 2b entry checklist: the transient-failure retry policy, where held drafts persist, that analysis sentences are checked by code only, that `normalised` is not compared with `raw`, the one-for-one revision limit, DNS rebinding, and unread style sheets.
